Bayesian inference and MCMC: from likelihood to simulation

Derive a posterior by hand, construct a Metropolis kernel and check an actual sampler.

Method

Read deliberately: define every symbol, reproduce the example without looking, execute the code, solve the exercises, then watch supplementary lectures. Derivations come first.

Bayesian updating

A Beta(2,2) prior yields a Beta(2+k,12−k) posterior.

01 — What is unknown?

Observe k=7 successes in n=10 independent trials with an unknown common probability θ∈(0,1). The likelihood of k is p(k|θ)=C(n,k)θᵏ(1−θ)ⁿ⁻ᵏ; as a function of θ, this is not itself a probability density for the parameter. Bayesian inference multiplies it by a prior p(θ) and normalizes.

With a Beta(a,b) prior proportional to θᵃ⁻¹(1−θ)ᵇ⁻¹, Bayes yields p(θ|k)∝θᵃ⁺ᵏ⁻¹(1−θ)ᵇ⁺ⁿ⁻ᵏ⁻¹. Therefore the posterior is exactly Beta(a+k,b+n−k). This is Beta–Binomial conjugacy, not an approximation.

02 — Numeric example and prediction

Choose θ∼Beta(2,2). Following 7 successes and 3 failures, θ|k∼Beta(9,5). Its posterior mean is 9/(9+5)=9/14≈0.6429, not 7/10, because the prior contributes information. Its variance is 9·5 / ((14)²·15)≈0.01531. The posterior-predictive probability of success on the next trial equals E[θ|k]=9/14. A 95% credible interval uses the posterior's 2.5% and 97.5% quantiles. It expresses conditional probability about parameters under this model, not repeated-sampling confidence-interval coverage.

03 — Why do we need MCMC?

Conjugacy makes the posterior easy here. But in hierarchical models, survival models or Bayesian deep networks, p(D)=∫p(D|θ)p(θ)dθ can be intractable. MCMC builds a Markov chain targeting posterior π(θ). Metropolis–Hastings proposes θ′∼q(·|θ) and accepts with α=min(1,[π(θ′)q(θ|θ′)]/[π(θ)q(θ′|θ)]). The unknown normalization constant cancels; so does the proposal ratio if proposals are symmetric.

Detailed balance, π(θ)P(θ,θ′)=π(θ′)P(θ′,θ), explains why the transition kernel preserves the target. Irreducibility and ergodicity matter too; invariance alone does not guarantee that a short run approximates the posterior well.

04 — The transformation trap

A Gaussian random walk on θ can step outside (0,1). Instead use z=logit(θ)=log(θ/(1−θ)). The transformed density satisfies πz(z)=πθ(sigmoid(z))×sigmoid(z)(1−sigmoid(z)). The second term is the Jacobian of the inverse transformation. Do not omit it. For Beta(A,B), transformed log-density (up to a constant) is A·log(θ)+B·log(1−θ), not (A−1)log(θ)+(B−1)log(1−θ).

Check multiple chains, acceptance rates, traces, autocorrelation, effective sample size and initialization sensitivity. Successive draws are correlated; 10,000 iterations are not automatically equivalent to 10,000 independent samples.

05 — Implement and verify

The following code uses NumPy to make each operation explicit and testable. Run it in a local notebook or standard Python environment. Neither a GPU nor personal data is required.

import numpy as np
rng = np.random.default_rng(2026)
A, B = 9, 5                       # posterior Beta(9,5)
def sigmoid(z):
    return 1 / (1 + np.exp(-z))
def log_target_z(z):
    # Stable log(sigmoid(z)) and log(1-sigmoid(z))
    return -A * np.logaddexp(0, -z) - B * np.logaddexp(0, z)
z = 0.0
draws = []
accepted = 0
for i in range(35000):
    candidate = z + rng.normal(scale=0.75)
    log_ratio = log_target_z(candidate) - log_target_z(z)
    if np.log(rng.uniform()) < log_ratio:
        z = candidate
        accepted += 1
    if i >= 5000:
        draws.append(sigmoid(z))
print("Metropolis posterior mean:", np.mean(draws))
print("Exact posterior mean:", A / (A + B))
print("Acceptance:", accepted / 35000)

06 — Exercise and solution

Replace the prior with Beta(1,1). What posterior follows after 7 of 10 successes? Compute its mean. Why does the Jacobian appear under θ-to-z transformation?

Show worked solution

The posterior is Beta(8,4), with mean 8/12=2/3. Density transforms by conserving probability mass: pz(z)dz=pθ(θ)dθ.
