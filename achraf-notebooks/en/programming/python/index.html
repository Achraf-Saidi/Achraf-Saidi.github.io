Python: from calculation to a reproducible experiment

50 min · Reading & practice

Why write a program?

Section titled “Why write a program?”

You measure three values: 2, 4 and 6. Their mean is (2+4+6)/3=4(2+4+6)/3=4(2+4+6)/3=4. This is easy by hand; code becomes useful when you repeat calculations, inspect steps and share the exact method. We will build a readable procedure whose expected result is known before execution.

Prerequisite: fractions. No programming background required. By the end, you will manipulate numerical lists, define functions and test their behaviour.

Naming a value

Section titled “Naming a value”

In Python, x = 2 binds the name x to an integer object. The statement x = x + 1 rebinds it to 3; it is not the mathematical assertion x=x+1x=x+1x=x+1. Equality is tested with ==. Integers have type int, approximate decimal numbers type float, and text type str.

The statement values = [2, 4, 6] creates an ordered list. values[0] is 2 because indexing starts at zero. len(values) gives length 3. An absent index raises an error rather than inventing a value. Lists may mix types, but a mean function needs inputs compatible with arithmetic.

Repeating an operation

Section titled “Repeating an operation”

The for loop takes each list element in turn. Indentation marks its repeated block. The running total becomes 2, then 6, then 12. Division occurs after the loop. The function print displays a value; it does not return that value for a later calculation.

Libraries after mechanisms

Section titled “Libraries after mechanisms”

The standard library provides statistics.mean([2,4,6]). NumPy suits large homogeneous arrays: np.mean(array) expresses a calculation over an array. Libraries do not eliminate semantic checks: missing values, a text column or the wrong axis can change a result’s meaning.

In a real project, save code in a .py file, document the Python version and dependencies, and separate raw data from outputs. Notebooks explain experiments well; tested reusable functions help avoid inconsistencies caused by cells executed out of order.

A precision issue

Section titled “A precision issue”

The expression 0.1 + 0.2 == 0.3 is false under Python’s usual floating-point arithmetic because binary representations approximate these decimals. Use math.isclose to compare approximate results, selecting tolerances appropriate to your problem. A tolerance does not excuse errors: it should reflect scale and expected numerical precision.
